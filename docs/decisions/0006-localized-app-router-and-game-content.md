# ADR 0006：语言前缀 App Router 与版本化游戏内容本地化

- 状态：已接受
- 日期：2026-07-28

## 背景

Web 当前使用 Next.js 15 App Router，但页面路由没有语言段，组件、日期格式和数据库浏览器投影
大量固定为中文或 `zh-CN`。统一游戏目录已经以稳定英文 ID、文本键和多 locale 本地化记录保存
帕鲁、被动、主动技能和伙伴技能事实，因此 UI 文案不能与游戏事实混入同一消息来源。

## 决策

1. 页面使用顶层 `app/[locale]`，公开语言固定为 `zh` 与 `en`，前缀始终存在。
2. 当前 Next.js 15 继续使用 `middleware.ts`，组合 locale negotiation 与现有 Supabase 鉴权；API、
   内部资源和静态资产不进入语言路由。
3. 使用 `next-intl` 管理应用消息、ICU 插值、日期/数字格式和 locale-aware 导航。应用消息按功能
   命名空间组织并检查中英文键一致性。
4. URL locale 与目录 locale 分离：`zh -> zh-CN`、`en -> en-US`。所有游戏名称与描述从固定
   `game_data_version_id` 的 `catalog_localizations` 读取，不复制到应用消息。
5. locale-aware 数据库读取使用新的前向版本 RPC；旧 RPC 保留兼容。翻译缺失时返回可识别的
   缺失事实，由 Web 使用当前语言的中性消息展示，绝不显示稳定内部 ID。
6. AI 自由文本记录生成语言。语言不匹配时展示从稳定路线指标与解释代码生成的本地模板，历史
   结果保持不可变。

## 结果

- 书签、筛选和动态详情页可在语言切换后保持同一资源与查询状态。
- UI 翻译可独立演进，游戏名称仍受目录版本、来源与发布门禁约束。
- 新增语言只需扩展路由、应用消息、目录 locale 映射与发布覆盖检查，不修改确定性配种算法。
- 迁移横跨 Web、共享契约、数据库与 Agent，必须使用失败测试、向前迁移和跨层最终验证。
