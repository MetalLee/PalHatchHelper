# 开发原则

1. 正式规格是唯一需求来源，按分阶段计划交付并独立验收。
2. 安全默认：Agent 只主动出站；原始存档只读；秘密只进入运行环境。
3. 契约优先：共享 JSON Schema/OpenAPI 是业务字段来源，TS 与 Pydantic 模型必须由同一来源生成或验证。
4. 确定性核心：配种关系、合法性和基础评分来自版本化数据与算法；AI 只解释和辅助排序。
5. 可复现：库存快照、配种数据、算法和评分版本固定在任务与计划上；时间用 UTC。
6. 可替换：Supabase、Parser、数据源和 AI Provider 均通过 Adapter 隔离。
7. 小步验证：先写失败测试或结构检查，再做最小实现，最后运行完整 lint、格式、类型、测试和构建。
8. 稳定接口：内部英文 ID、稳定错误码和职责单一文件优先于依赖错误文本或隐式约定。

Phase 0 不接入真实 Supabase 或存档，避免在权限、快照协议和 ParserAdapter 尚未测试前扩大数据与生产风险。
